# necode.sh

C++ をコンパイルして実行する Bash スクリプトです。スクリプトの置き場所、ユーザー名、フォルダ名には依存しません。macOS / Linux の Bash で動作し、`--paste` は macOS の `pbpaste` を使います。

## インストール

Git と C++23 対応コンパイラを用意して、好きな場所に clone してください。

```sh
mkdir -p "$HOME/git_station"
git clone https://github.com/tuttu630tttu/necode.git "$HOME/git_station/necode"
"$HOME/git_station/necode/necode.sh" --help
```

`"$HOME/git_station"`は一例で、clone 先の名前や場所は自由です。実行権限は Git に記録されています。コンパイラと AtCoder Library 自体は別途インストールしてください。（AtCoder Library はなくても動作します。）

## 使い方

> `main.cpp` は実行したい C++ ソースファイルのパスに置き換えてください。

以下の例は、clone 先の `necode` ディレクトリ内で実行します。相対パスは現在のディレクトリを基準に指定します。

### 通常実行

```sh
./necode.sh main.cpp
```

### ペースト実行

```sh
./necode.sh main.cpp --paste
```

### ヘルプ表示

```sh
./necode.sh --help
```

> 後述のキーショートカット（[VS Code](#vscode-keybind) / [Neovim](#neovim-keymap)）を設定すれば、コマンドを入力せずに実行できます。個人的にはこちらの方がおすすめです。

### 引数とパスの指定

ファイルには絶対パス・相対パスの両方を指定できます。空白があるパスは引用符で囲んでください。オプションはファイル名の前後どちらでも指定できます。

> **引数指定上での注意点の補足：**
>
> パスに空白がある場合はダブルクォートで囲んで1つの引数として渡してください。スクリプト側とソース側のパスは、それぞれ別に囲みます。
>
> また、`"~/..."` の `~` は展開されません。
>
> ```sh
> "$HOME/git_station/necode/necode.sh" "$HOME/cpp_code/空白 あり.cpp" --paste
> ```
>
> そのため、引用符の中では `"$HOME/..."` を使ってください。


### コンパイルと失敗時の再実行

通常は `-std=c++23 -O2 -Wall -Wextra -Wshadow -D_GLIBCXX_DEBUG` でコンパイル・実行します。

`--paste` で実行したプログラムが非ゼロの終了コードで失敗すると、警告・デバッグ指定を外して再コンパイルし、**同じ入力での実行結果**も表示します。再実行時も `-std=c++23 -O2` と ACL の include 指定は保ちます。

> 更新（2026-10-13）：`--paste` の失敗時は自動で再実行する方式に変更しました。`--no-debug` や切り替え用 keybind は不要です。

#### 補足・注意点

- 警告だけの場合、コンパイルエラーの場合、Ctrl+C で中断した場合は再実行しません。
- 再実行に成功しても、スクリプトは最初の失敗の終了コードを返します。
- `_GLIBCXX_DEBUG` は GNU の標準ライブラリの検査機能です。外す指定は `-Wall -Wextra -Wshadow -D_GLIBCXX_DEBUG` です。ACL などが行う `assert` の検査は残ります。
- 不正アクセスなどによる未定義動作は、検査を外しても正しくなるわけではありません。再実行の結果は原因を調べる参考にしてください。

### 入力方式

#### 手入力（`--paste` の指定なし）

標準入力を直接プログラムに渡します。入力なしのプログラムはすぐに実行でき、必要な個数の入力を読むプログラムなら、読み終わると処理が進みます。手入力モードでは自動再実行しません。

#### ペースト入力（`--paste`）

スクリプト開始時にクリップボードを保存し、標準入力として渡します。コンパイル中に別の内容をコピーしても、その実行と自動再実行には最初に保存した入力を使います。

入力の一時ファイルと、デバッグ指定を外して作成した実行ファイルは終了時に削除します。

#### 補足・注意点

- 手入力で EOF まで読むプログラムには、Ctrl+D などで EOF を送ってください。決まった個数だけ読むプログラムでは不要です。
- クリップボードを取得するのは、キーを押した瞬間ではなくスクリプトが起動した直後です。起動前にコピーし直した内容は、その実行の入力になる場合があります。

### コンパイラの指定

コンパイラは `g++-16` → `g++-15` → `g++-14` → `g++` → `clang++` の順に探します。C++23 に対応したコンパイラが必要です。指定する場合は `CXX` に実行ファイル名またはパスを設定してください（追加フラグは含めません）。

```sh
CXX=clang++ ./necode.sh main.cpp
```

## 入力と出力の区切り

`--paste` でターミナルに表示するときは、クリップボードの入力とプログラムの出力を見出しで区切ります。入力の末尾に改行がなくても、出力は新しい行から表示します。

```text
--- INPUT ---
2 3

--- OUTPUT ---
5
```

標準出力をファイルやパイプへ渡す場合は、入力の再表示と見出しを出さず、プログラムの出力だけを渡します。手入力モードは従来どおり直接プログラムへ入力します。

<a id="execution-time"></a>

## C++ の実行時間

実行が終わると、標準エラー出力に時間を表示します。コンパイル、クリップボードの取得、シェルスクリプトの準備、stderr を整形する処理の終了待ちは計測に含めません。失敗後に再実行した場合は、それぞれの時間が表示されます。

```text
[time] real 0.012 s | user 0.009 s | sys 0.002 s
```

- `real`: C++ のプロセスが動いていた実経過時間。入力待ちや I/O 待ちも含みます。
- `user`: プログラムがユーザーモードで使った CPU 時間。
- `sys`: プログラムのために OS が使った CPU 時間。

### 実行時間の見方

手入力の待ち時間も `real` に含まれます。処理時間を比べたいときは `--paste` を使うと便利です。時間表示は標準エラー出力に出し、答えの標準出力には混ぜません。

### 補足・注意点

- 計測対象は C++ プロセス全体で、プロセスの起動・終了に伴う処理も含みます。特定の関数だけを測るものではありません。
- マシンの性能やデバッグ指定が異なるため、提出先の実行時間と一致するとは限りません。

## デバッグ出力の表示

プログラムの `std::cerr`（標準エラー出力）は、各行の先頭に `[stderr]` を付けて表示します。ターミナルでは目印を黄色にします。`cpp` 側の変更や追加の keybind は不要で、手入力・ペースト・デバッグ指定を外した再実行のいずれにも対応します。

```text
2 2
[stderr]  1 1
[stderr]  2 1
```

`std::cout` の内容はそのまま表示します。ターミナルでは stderr の先頭に改行を入れ、答えと目印を区切ります。

コンパイラの警告・エラーは元の表示を保ちます。実行時の例外や標準ライブラリのエラーも stderr として目印が付きます。色が不要なら `NO_COLOR=1` を指定できます。ファイルへリダイレクトする場合は色を付けません。

### 行ごとの色分け

`cerr` の行頭にタグを書くだけで、目印の色を切り替えられます。タグなしの行は従来どおり黄色の `[stderr]` です。

```cpp
cerr << "[info] n=" << n << '\n';       // 水色
cerr << "[debug] i=" << i << '\n';      // 紫
cerr << "[warn] 想定外の値" << '\n';    // 黄
cerr << "[error] 範囲外" << '\n';       // 赤
cerr << "[success] チェック完了" << '\n'; // 緑
cerr << "[blue] 左側の探索" << '\n';    // 青
cerr << "[magenta] 右側の探索" << '\n'; // 紫
```

#### タグと色の一覧

| タグ | 色 |
| --- | --- |
| `[trace]`, `[gray]` | グレー |
| `[debug]`, `[magenta]` | 紫 |
| `[info]`, `[cyan]` | 水色 |
| `[warn]`, `[yellow]` | 黄 |
| `[error]`, `[red]` | 赤 |
| `[success]`, `[green]` | 緑 |
| `[blue]` | 青 |
| `[white]` | 白 |

#### タグ欄の整列

タグ欄は9文字幅に固定し、本文はすべて同じ桁から表示します。タグの ANSI 色コードは幅に数えません。本文に書いた追加の空白はそのまま残します。

```text
[debug]   10
[red]     100
[success] 1000
[stderr]  10000
```

大文字の `[ERROR]` なども使えます。認識したタグはそのまま色付きの目印になり、`[stderr]` は重ねて付けません。行頭以外や未対応のタグは通常の stderr として表示します。色はタグ部分だけに付け、本文は読みやすい通常色を保ちます。改行ごとにタグを指定してください。`cerr << "[info] ..."` を何回かに分けて書いても、同じ行が完成した時点で処理します。

`NO_COLOR=1`、`TERM=dumb`、ファイルへのリダイレクトではタグを残して色だけを無効にします。標準出力・コンパイラの警告は色分けの対象外です。手入力とペースト、失敗後の再実行で共通の動作です。

### 補足・注意点

- `stdout` と `stderr` を頻繁に交互に出力すると、表示順序や行の並びが前後する場合があります。
- stderr は行単位で整形します。改行のない途中の出力は、行が完成するかプログラムが終了した時点で表示されます。

## 出力先と ACL

### 作業ルートと出力先

ソースのある Git リポジトリのルートを作業ルートとして自動検出します。Git 管理外ならソースのあるディレクトリを使います。呼び出したターミナルの現在地やスクリプトの置き場所には依存しません。

```text
作業ルート/
├── ac-library/
├── main.cpp                 → out/main/main
├── shojin/a.cpp             → out/shojin/a
└── out/
```

### ACL と環境変数

作業ルートの `ac-library/` があれば自動で include パスに追加します。別の場所に置く場合や Git 管理外の作業フォルダをまとめる場合は、環境変数で設定できます。

```sh
export NECODE_ROOT="$HOME/cpp_code"
export NECODE_ACL_DIR="$HOME/libraries/ac-library"
# 任意: 出力先を変更
export NECODE_OUT_DIR="$HOME/cpp-binaries"
```

`NECODE_ROOT` を指定する場合、ソースはその中に置いてください。`NECODE_OUT_DIR` と `NECODE_ACL_DIR` に相対パスを指定すると、呼び出した現在地からのパスになります。複数の作業ルートで同じ出力先を共有すると同名の相対パスが上書きされるため、出力先は作業ルートごとに分けてください。

プログラムの実行時の現在地は呼び出したターミナルの現在地を引き継ぎます。

<a id="command-path"></a>

## どこからでも呼び出す（PATH）

clone 先のリポジトリで、最初に実行権限を確認します。

```sh
chmod +x necode.sh
```

PATH は、`necode.sh` のように名前だけで呼んだコマンドを探すフォルダの一覧です。スクリプトは移動もコピーもされません。`/Users/.../shojin/necode.sh` のようにパスを指定した場合は PATH を使わず、その場所を直接探します。

そのディレクトリの絶対パスを PATH に追加すれば使えます。例えば `~/.zshrc` に次を追加します（clone 先に合わせて変更してください）。

```sh
export PATH="$HOME/git_station/necode:$PATH"
```

新しいターミナルを開くか `source ~/.zshrc` を実行した後は、どのディレクトリでも次のように呼び出せます。

```sh
necode.sh /path/to/source.cpp --paste
```

ユーザー名をスクリプトに書く必要はありません。`$HOME` はシェルが設定します。リポジトリ名を `necode` などに変更したり、`necode.sh` だけ別リポジトリに移したりしても動作します。コンパイラや ACL 自体は別途用意してください。

## VS Code の keybind

### 設定の追加

設定例の全体は [examples/keybindings.json](examples/keybindings.json) に置いています。VS Code の「基本設定: キーボード ショートカットを開く (JSON)」で開くユーザー設定に、必要な項目だけ統合してください。

`~/git_station/necode` に置いて PATH を設定せずに使う場合、`keybindings.json` の実行部分を次に変更します。`$HOME` はターミナルのシェルがホームディレクトリに展開するので、ユーザー名も固定しません。

```json
"text": "\"$HOME/git_station/necode/necode.sh\" \"${file}\" --paste\u000d"
```

### キーと入力方式の変更

キーは自由に決められます。設定例の `Ctrl+;`・`Ctrl+L` は作者の割り当ての一例です。ペースト入力には `--paste` を付け、手入力には付けません。

キーを変更する場合は、各設定の **`"key"`**（例：`"ctrl+;"`）を書き換えます。実行内容は **`"text"`** で指定します。

### スクリプトのパスと PATH

`${workspaceFolder}` を使わないので、別のフォルダや単独の C++ ファイルでも同じコマンドを使えます。スクリプトを移動した場合は、このパスを変更してください。PATH を設定した場合は `\"$HOME/git_station/necode/necode.sh\"` を `necode.sh` に置き換えることもできます。PATH の設定後は VS Code のターミナルも開き直してください。

`sendSequence` の変数展開については [VS Code 公式ドキュメント](https://code.visualstudio.com/docs/terminal/advanced) を参照してください。

## Neovim の keymap（LazyVim / snacks.nvim）

### 前提

Neovim では、現在開いている C++ ファイルを保存して、内蔵ターミナルで `necode.sh` を実行できます。以下は **LazyVim と snacks.nvim のターミナル機能を使う設定例**です。素の Neovim だけでは `Snacks.terminal` は使えないため、LazyVim を使わない場合も [snacks.nvim の terminal 機能](https://github.com/folke/snacks.nvim/blob/main/docs/terminal.md) を利用できる状態にしてください。

### 設定例の読み込み

先に上の手順で `necode` とコンパイラを用意し、LazyVim の `~/.config/nvim/lua/config/keymaps.lua` から設定例を読み込みます。[LazyVim ではこのファイルが自動読み込みされます](https://www.lazyvim.org/configuration/general)。既存の設定は残し、同じキーが使われている場合は割り当てを調整してください。LazyVim 以外の構成では、このコードを自身の設定から読み込んでください。

設定例内の `local script` は clone 先に合わせて変更します。スクリプトをパスで直接指定するため、シェルの PATH 設定は不要です。

設定例の全体は [examples/neovim-keymaps.lua](examples/neovim-keymaps.lua) に置いています。内容を `keymaps.lua` に追記するか、次の1行で読み込んでください（clone 先が異なる場合はパスを変更します）。

```lua
dofile(vim.fn.expand("~/git_station/necode/examples/neovim-keymaps.lua"))
```

### キーと入力方式の変更

キーは設定例の一例なので、既存の操作と競合しない好きなキーへ変更してください。例えば Neovim の `Ctrl+L` には既存の割り当てがあるため、そのまま使う必要はありません。

設定例の末尾にある **`vim.keymap.set` の第2引数**がキーです。`"<C-l>"`・`"<C-;>"`・`"<leader>nr"`・`"<leader>np"` の部分を変更します。第1引数は有効なモードで、`"n"` はノーマル、`"i"` はインサートです。`<leader>` は自身で設定したキーです。ターミナルによって `Ctrl+;` を区別できない場合は、別のキーを選んでください。

- `run_necode(true)` を呼ぶ設定：ペースト入力。
- `run_necode(false)` を呼ぶ設定：手入力。

`dofile(...)` で読み込む場合は `examples/neovim-keymaps.lua` を、コードをコピーした場合はコピー先の `keymaps.lua` を編集します。設定後は Neovim を開き直し、実行したい `.cpp` ファイルの編集ウィンドウで自分が設定したキーを押してください。

### 実行後の操作と動作

実行結果は下部のターミナルに残り、プログラムの実行中は手入力を受け付けます。終了・中断する前にもう一度実行すると、重複起動せず実行中のターミナルを表示します。終了後に編集ウィンドウから再実行すると、前の結果用ターミナルを閉じて新しい結果を表示します。プログラムを中断する場合はターミナルで `Ctrl+C`、編集へ戻る場合は `Ctrl+\` → `Ctrl+N` でターミナル入力モードを抜け、元の C++ ウィンドウへ移動してください。

ファイルは実行前に保存され、保存に失敗した場合は実行しません。作業ディレクトリはソースファイルのあるディレクトリです。コマンドを引数の配列で渡すため、パスに空白があっても扱えます。`--paste` はこの設定でも macOS の `pbpaste` を使います。

```sh
python3 -m unittest discover -s tests
```
